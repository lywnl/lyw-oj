# 题目索引同步

## Purpose

把题目主库的已提交行变更可靠地投影到搜索索引，使业务请求不再承担跨存储双写。保持判题数据来自主库，并在重复投递、断线、索引故障及历史差异下提供可核验的恢复和维护边界。

## ADDED Requirements

### Requirement: 完整行增量投影
系统 MUST 仅将指定业务库 tb_question 的 ROW/FULL 事件投影到 idx_question，正常增量不得读取题目表补充字段，必须保留完整字段与空值语义。

#### Scenario: 行变化直接更新索引
- **WHEN** 收到新增、修改、删除或主键变化事件
- **THEN** 使用完整变更后行覆盖新 ID 文档，删除使用原主键；同批同 ID 取源顺序最后操作

#### Scenario: 数据与格式验证
- **WHEN** 输入包含中文、空串、NULL、日期或大整数 ID，或者缺少必需行字段
- **THEN** 合法值无精度/时区损失；不完整或无法转换的行阻塞批次，不回查补列，不写部分默认数据

### Requirement: 可恢复的批次消费
系统 MUST 在所有 ES 操作成功后确认批次，失败不得跳过；只允许指定单执行者，断线和重启必须保留重放能力。

#### Scenario: 部分成功与确认不确定
- **WHEN** ES 部分失败、超时或 ACK 前后连接中断
- **THEN** 不丢弃未确认事件，重放可覆盖相同文档，重复删除成功，最终追平主库

#### Scenario: 容器重建续传
- **WHEN** Canal 容器使用原持久卷重新创建
- **THEN** 消费身份及已持久化位点保持，允许重复但不得静默改为最新位点

#### Scenario: ES 校验集中于生命周期边界
- **WHEN** 首次建立消费连接、故障后重连、开始新一轮自动对账，或进入 check/repair
- **THEN** 在对应工作开始前校验索引、映射及目标索引禁止隐式创建的策略；边界之间的正常批次和后续分页不重复执行整套元数据校验，但每次 bulk 仍逐项检查结果

#### Scenario: 首次校验后索引被删除
- **WHEN** 已通过校验的目标索引随后被删除，增量或自动修复尝试写入
- **THEN** 禁止隐式建索引，索引缺失错误阻塞同步及自动修复，不确认失败批次；不得把索引缺失误判为删除不存在文档成功

### Requirement: 阻塞与人工恢复
系统 MUST 在目标表 DDL/TRUNCATE、位点失效、映射不兼容或不可信行数据时停止增量及自动修复并记录原因；恢复不得静默清索引或跳历史。

#### Scenario: 非行变更及位点异常
- **WHEN** 检测到相关 DDL、TRUNCATE、失效位点或映射错误
- **THEN** 状态进入 BLOCKED，不确认该批，自动修复不继续，人工维护核对基线后才恢复

#### Scenario: 索引缺失与空库保护
- **WHEN** 普通同步发现索引不存在，或自动对账发现主库为空而索引仍有文档
- **THEN** 普通同步不能隐式建索引，自动对账不能以清空索引替代人工维护；显式维护可按已核对主库修复

### Requirement: 唯一索引写入与业务读路径
系统 MUST 移除请求路径的 ES 写入和自动建索引，详情与判题快照读取 MySQL；搜索使用 ES，并保持现有公开成功协议。

#### Scenario: 搜索故障不影响取题与组装提交
- **WHEN** ES 不可用，用户读取存在的题目或提交合法代码
- **THEN** 从 MySQL 取得详情、用例和限制，提交身份与结果查询协议不变，不触发索引回填

#### Scenario: 题目维护开关
- **WHEN** 维护已启用时调用题目新增、修改、删除
- **THEN** 返回错误码 3503 和“题库维护中，请稍后重试”，数据库不变；其他管理功能不受此开关限制

#### Scenario: 独立维护进程的控制边界
- **WHEN** 操作方执行一次性维护进程
- **THEN** check 保持只读，repair 要求明确的维护确认且维护进程自身不启动增量；在线实例停写、在途请求排空和原消费者退出由实际运维步骤确认，不把维护进程中的配置或本地锁视为跨进程控制

### Requirement: 保留索引的核对与修复
系统 MUST 提供只读 check 和受控 repair，按主库核对缺失、过期及多余文档，保留已有映射；数据库读取失败或未核对完成不得删除索引数据。

正常增量运行期间，系统 MUST 保留定期自动差异修复，沿用源位点屏障、候选变更作废和空库保护；本轮优化不将其降为仅告警。

#### Scenario: 既有索引差异处理
- **WHEN** 已有索引缺少历史题目、内容过期或存在多余文档
- **THEN** check 只报告，repair 定点修复，不删除索引；不存在的索引仅能由显式维护创建

#### Scenario: 对账调度与查询异常
- **WHEN** 自动对账与增量同时就绪，或主库读取失败
- **THEN** 同一执行者分时处理，每页让出消费机会；读取失败不解释为题目删除

### Requirement: 配置与切换边界
系统 MUST 固定 Canal 1.1.8 TCP 和 ROW/FULL，校验业务库、最小必要凭据及持久化配置，提供开发/生产配置和保留基线的切换流程。

#### Scenario: 切换不漏历史和新变化
- **WHEN** 进入题目维护窗口，关闭旧写入者并建立有效起点 P
- **THEN** 核对/修复既有索引后从 P 消费，恢复写入后的变化不丢失；不自动应用生产配置或重启真实数据库

#### Scenario: 生产持久化目录迁移
- **WHEN** 生产采用默认目录，或从旧目录迁移位点和配置
- **THEN** 默认目录位于正式部署目录；迁移在消费者和 Canal 停止后完整保留位点、TSDB、建立标记及配置，应用与 Canal 指向同一份 state，身份和有效游标延续；不能仅替换成空目录或跳到最新位置

### Requirement: 搜索可见性
系统 SHALL 在无积压且依赖正常的验收环境下，于事务提交后 5 秒内使新增、修改、删除对搜索可见。

#### Scenario: 真实搜索延迟
- **WHEN** 真实 MySQL 提交题目增删改
- **THEN** 不强制 refresh，使用 ES _search 确认 5 秒内反映最新状态，不能仅以实时 GET 文档代替
