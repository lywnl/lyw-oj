# Canal 完整行事件同步题目索引

## Why

初始问题是题目请求双写 MySQL 与 ES，以及用户端回填索引、从可能过期的索引读取判题用例。当前未提交实现已将索引写入集中到 Canal 消费者，保留既有索引并通过自动对账修复偏差。

本轮在保留自动修复的前提下优化三处实现：生产位点和配置默认位于工具临时目录，ES 元数据在每批写入及每页对账中重复校验，独立维护 JVM 的本地排空锁不能约束在线业务实例。

## What Changes

- Canal 1.1.8 TCP 订阅单表 ROW/FULL 事件，oj-system 单线程直接映射行数据写/删 ES，正常增量不查题目表。
- 完善批次确认、重试、位点持久化、阻塞状态、单写者及命令行 check/repair。
- 删除 B/C 端 ES 双写与自动建索引；详情和判题快照改读 MySQL，保持公开成功协议。
- 新增题目维护错误码 3503，保留索引与映射，提供开发/生产配置及保留基线的切换说明。
- 无同步 MQ、Outbox、新业务服务、源版本列、自动选主或自动归档/发布。
- 本轮优化生产持久化目录、ES 校验触发边界和维护入口；保留自动修复及其位点屏障、候选失效检查、空事务配置、源位点检查和连接超时。
- 反向对账只查询题目 ID 暂列候选，不纳入本轮必需实施任务；不把自动修复改为人工修复，不迁移到 XXL-JOB。

## Capabilities

### New Capabilities
- `question/index-sync`：题目完整行增量投影、查询边界、维护对账和恢复。

### Modified Capabilities
无。现有 judge/container-pool 的调度及判题结果协议不变。
