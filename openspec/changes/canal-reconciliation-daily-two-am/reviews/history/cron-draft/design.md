# Design

## Context

参见 proposal.md。当前使用 `now + reconcileIntervalMillis`，连接成功及每轮结束都会重置时间。`tick(long now)` 已可用可控时间验证，分页修复与增量属于同一线程。Spring 依赖已提供 `CronExpression`，不需要新增库。已有测试和隔离集成探针用显式毫秒间隔加快验证。

## Goals / Non-Goals

默认每日北京时间 02:00，保留原单线程和修复协议；本次只修改调度与相关配置、测试和说明。不新增调度线程、分布式锁、调度记录表或真实环境操作，不更改原 500 条分页、空闲拉取 1 秒和候选等待上限。

## Decisions

1. 增加内部 `ReconciliationSchedule` 封装时区、cron 解析、启停与下一时刻计算，默认 `0 0 2 * * *`，时区固定 `Asia/Shanghai`。复用 Spring 的解析器，避免手写不完整的日历规则；不用另一个线程写 ES。
2. 旧 `reconcileIntervalMillis` 改为可空配置。未配置使用日历；显式值保留优先级与原间隔行为，启动时提示迁移。旧 0 保持关闭，新的关闭方式为 `reconcile-cron: "-"`。仓库开发和生产配置没有旧覆盖，因此默认直接切换；线上若有覆盖，维护说明要求移除旧配置。
3. 每次消费线程启动时重新初始化调度；在首次可能失败的连接操作前记录触发点。断连只重置对账工作状态，不清除日历触发点。错过时最多重新开始当前到期轮次，不创建多个历史任务。
4. 已启动轮次继续分页。完成或候选超时结束后计算严格晚于当前观察时间及本轮触发点的下次执行，避免完成时长导致漂移及回拨导致立即重复。初次恰好到点允许执行；初次已过点则等待次日。
5. 保留旧间隔模式的重连与完成后相对间隔语义，作为迁移兼容路径；默认日历模式才保留跨重连的到期任务。测试使用显式旧配置的既有探针继续有效。

## Risks / Trade-offs

- 消费线程需要完成当前操作后才能进入对账，02:00 是计划触发点，不是毫秒级硬实时保证；不承诺完成时刻。
- 调度状态只在内存，不跨进程保存历史运行日期；停机错过当天时刻后新进程等待下一次，不增加持久化恢复系统。
- 临时故障沿用既有重连；阻塞性错误仍停止消费和自动对账。失败或跨日可影响实际执行次数，不能把每日计划称为故障下严格恰好一次。
- 显式旧间隔会覆盖默认日历，必须在部署时核对；本轮不访问或修改真实 Nacos。

## Validation

纯日历测试覆盖当天前后、整点、跨月跨年、其他默认时区、关闭、非法值与旧配置。消费测试覆盖到点触发、全天不重复、分页让出、首次连接跨时刻恢复、跨日不并发、回拨以及现有 ACK/异常退出回归；配置绑定通过真实 Spring Binder 验证。运行现有同步单元与本地 HTTP 测试，不启动真实 MySQL/Canal/ES。测试产物使用既有 Docker/JDK 17 脚本和唯一标签，保留必要证据并清理本轮构建及容器。

## Migration Plan

默认无需新增部署参数；若已有旧间隔，移除它并设置或沿用 `reconcile-cron: "0 0 2 * * *"`，再按既有单消费者方式重启。保留关闭值 `-` 的文档。回退代码时恢复旧配置，不修改数据库或 Canal state。本轮不执行部署。
