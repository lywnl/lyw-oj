# 容器池沙箱防护

## Why

池化执行在编译阶段无限等待，运行超时后仅删除源码而复用仍可能执行的容器；CPU 配置使用 Linux 不适用的 CpuCount，输出和任务文件也缺少完整控制。需要在保留既有调度方式的前提下，限制单次提交并可靠隔离异常执行环境。

## What Changes

- 增加 Linux CPU 配额、PIDs 限额和新容器准入检查。
- 编译等待有界，运行等待采用 max(配置最低等待值，题目时限加缓冲)。
- 超时、输出超限、基础设施异常触发隔离回收；回收失败保留资源名额，避免超额补建。
- 完整清理任务文件，限制一次提交所有输出的累计字节，确认清理后才完成任务。
- 调整池化内部 Java 接口传入题目时限，外部 HTTP、MQ、结果模型和非池化链路保持原约定。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `judge/container-pool`：增加执行资源限制、执行等待和输出边界，修订异常回收及容量规则。

## Impact

实现集中在 oj-judge 的容器池、执行服务、配置、任务结果及专用回调；增加 docker-java-transport-httpclient5:3.3.4 用于控制请求与执行流，保留共享控制客户端及每 Worker 独占执行流客户端的生命周期边界。不增加限流、内存统计口径改造、后台子进程追踪或自动恢复系统。
