## MODIFIED Requirements

### Requirement: 前端必须在限定窗口内继续查询迟到真实结果

前端 SHALL 在收到 ID 后立即发起首次查询并保持串行；每次未取得最终结果的正常响应结束后，依次等待 200、400、800 毫秒，后续保持 800 毫秒。每轮重新开始时 SHALL 重置退避。单请求上限 5 秒，单轮总预算 60 秒包含第 55 秒开始的最终核对。SYSTEM_ERROR 只展示临时提示，不重置退避或窗口；JUDGED、查询异常、窗口结束或页面上下文变化终止当前查询。

#### Scenario: 临时错误后出现真实结果
- **WHEN** 先收到 SYSTEM_ERROR，后续成功查询在窗口内获得 JUDGED
- **THEN** 页面持续查询并用真实结果替换提示，不重新提交代码；反复系统错误不延长窗口或重置退避

#### Scenario: 最终核对与手动重新查询
- **WHEN** 普通等待准备结束或用户对原 ID 点击重新查询
- **THEN** 自动等待在第 55 秒进入最终核对且只核对一次；手动操作立即核对一次，无最终结果时等待 200 毫秒后继续普通查询并逐步退避，所有请求受剩余预算约束

#### Scenario: 迟到响应与查询失败
- **WHEN** 切题、离开、新提交、超时或查询异常发生
- **THEN** 旧响应不更新新页面，取消不弹错误；暂停后保留 ID 供重新查询，不能声称后台任务被取消或自动重试

#### Scenario: 首查立即执行且间隔有上限
- **WHEN** 同一轮查询依次得到多个 NO_RESULT 或 SYSTEM_ERROR
- **THEN** 首查无初始等待；后续等待为 200、400、800、800 毫秒，不因状态在二者间切换而重置；取得 JUDGED 后不再调度查询

#### Scenario: 请求耗时不计入等待间隔
- **WHEN** 一次查询响应耗时超过下一次等待间隔
- **THEN** 等待仍从该请求结束后计算，期间不发起另一条普通查询，同一轮最多一个有效在途请求

#### Scenario: 新查询轮次重新开始退避
- **WHEN** 原轮次已达到 800 毫秒等待，随后新提交或手动重新查询启动新轮次
- **THEN** 新轮次立即查询，后续从 200 毫秒重新退避；原轮次的等待任务不能发出新请求
