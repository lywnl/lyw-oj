## Purpose

让用户能够以稳定的提交标识获取自己的判题结果，在消息重发、并发消费、缓存故障和临时系统失败时保留真实结果，并以有限时间的前端查询反馈当前可获得的状态，避免重复记录和错误提示覆盖真实结果。

## ADDED Requirements

### Requirement: 同一次提交必须使用固定身份

系统 SHALL 在校验通过后为每次主动提交生成一次 submitId，所有消息重发和消费重试沿用该值；接口返回字符串 ID。查询 SHALL 仅定位登录用户的该次提交，不支持旧题号与时间组合。

#### Scenario: 提交回执和发送不确定
- **WHEN** 已分配 ID 的提交发送成功或发送失败
- **THEN** 回执或业务码 3701 的错误数据包含同一个 submitId，客户端不自动重新提交代码

#### Scenario: 非法身份与越权
- **WHEN** 查询 ID 缺失、非法，或提交属于其他用户
- **THEN** 非法 ID 返回参数错误，任何路径不得泄露其他用户的结果；缺少必要 ID 的消息不得判题或入库

### Requirement: 真实判题记录必须入库幂等

系统 SHALL 以 submitId 保证最多一条真实判题记录；每次消费先查询并复用已保存结果，主键竞争失败者使用已提交的同一记录。系统异常 SHALL NOT 写入提交表；并发重复运行沙箱不在本能力禁止范围内。

#### Scenario: 并发判题与插入冲突
- **WHEN** 两次同 ID 消费均未查到结果并分别得到真实结果
- **THEN** 最多一次插入成功，另一方复用数据库记录并正常确认，不能因主键冲突写系统错误或进入死信

#### Scenario: 确认前断连
- **WHEN** 真实结果已保存而消息未确认便发生连接中断
- **THEN** 重投消费直接复用已保存记录，不再次判题或插入

#### Scenario: 用户程序错误与系统故障
- **WHEN** 得到明确的用户代码失败或发生容器、通信、空结果等系统故障
- **THEN** 前者可成为真实的未通过记录，后者不产生提交记录且只提供临时系统提示

### Requirement: 统一结果缓存必须防止真实状态降级

系统 SHALL 按用户和 submitId 使用单一结果缓存，真实结果只来自已提交数据库记录。等待和临时错误不能覆盖已有真实结果，真实结果可以替换临时错误；读取与重复同级更新不得续期或删除缓存。

#### Scenario: 状态更新竞争
- **WHEN** 系统错误与真实结果以任意顺序或并发更新同一个有效缓存
- **THEN** 已存在真实结果不被降级，后到真实结果替换等待或错误；同级更新和晚到等待保持原值及剩余有效期

#### Scenario: 缓存过期与恢复
- **WHEN** 结果缓存过期或真实结果缓存更新失败
- **THEN** 数据库真实结果仍保留，后续核对能够返回它且尽力恢复缓存

### Requirement: 查询必须区分暂时无结果与依赖故障

系统 SHALL 返回 JUDGED、SYSTEM_ERROR 或 NO_RESULT；普通查询在 Redis 正常时不回源，显式核对或 Redis 读取异常时允许查询数据库。已查到数据库真实结果时，回填失败不得导致响应失败。

#### Scenario: 普通缓存查询
- **WHEN** 普通查询读到等待、临时错误、真实结果或确认键不存在
- **THEN** 不查询数据库；分别返回 NO_RESULT、SYSTEM_ERROR、JUDGED 或 NO_RESULT

#### Scenario: 数据库核对与缓存故障
- **WHEN** 用户显式核对或 Redis 读取发生异常
- **THEN** 优先返回查到的数据库真实结果；数据库异常，或无记录且缓存状态无法确认时返回查询错误 2000，不伪装为 NO_RESULT

### Requirement: 前端必须在限定窗口内继续查询迟到真实结果

前端 SHALL 在收到 ID 后串行查询，正常请求结束后间隔 2 秒，单轮总预算 60 秒包含最后一次核对。SYSTEM_ERROR 只展示临时提示，不停止或重置窗口；JUDGED、查询异常、窗口结束或页面上下文变化终止当前查询。

#### Scenario: 临时错误后出现真实结果
- **WHEN** 先收到 SYSTEM_ERROR，后续成功查询在窗口内获得 JUDGED
- **THEN** 页面持续查询并用真实结果替换提示，不重新提交代码；反复系统错误不延长窗口

#### Scenario: 最终核对与手动重新查询
- **WHEN** 普通等待准备结束或用户对原 ID 点击重新查询
- **THEN** 自动等待末尾只核对一次；手动操作先核对一次，必要时再开始限时缓存查询，所有请求受剩余预算约束

#### Scenario: 迟到响应与查询失败
- **WHEN** 切题、离开、新提交、超时或查询异常发生
- **THEN** 旧响应不更新新页面，取消不弹错误；暂停后保留 ID 供重新查询，不能声称后台任务被取消或自动重试
